## 1. Problem Statement

Local inference of a modern 8B model (Qwen3-8B) faces a trade-off between three backends on consumer hardware: **vLLM** (server-grade, GPU), **llama.cpp** (cross-platform CPU/GPU), and **MLX** (Apple Silicon). Each has different hardware requirements, throughput characteristics, and licensing. Choosing the wrong one can halve inference speed or block deployment entirely.

## 2. Background & Related Work

- **vLLM** introduced **PagedAttention** (Kwon et al., 2023) — memory-efficient KV-cache management via virtual pages, achieving 2-4x throughput vs naive serving.
- **llama.cpp** (ggerganov, 2023) brought GGUF quantization and CPU/GPU inference to consumer hardware. Q4_K_M quantization reduces an 8B model from ~16GB (FP16) to ~4.6GB with 3-6% quality loss.
- **MLX** (Apple, 2024) is Apple's array framework for Apple Silicon, with `mlx-lm` providing a llama.cpp-compatible inference API.
- **LM Studio** rebranded to **Bionic** in July 2026 — wraps llama.cpp (GGUF) + MLX, not a separate engine. [1]

## 3. Comparative Analysis

|---|---|---|---|

### 3.1 Throughput

vLLM leads on NVIDIA GPUs by **30–50%** over llama.cpp due to PagedAttention + continuous batching. On Apple Silicon, mlx-lm is the only practical choice (llama.cpp Metal is significantly slower).

### 3.2 Memory

All three backends load the same quantized model weights. KV-cache is the differentiator: vLLM shares KV pages across requests (~10x less VRAM), llama.cpp reserves per-request, MLX is in between.

### 3.3 Hardware compatibility

- **Windows + NVIDIA GPU** → vLLM or llama.cpp
- **macOS M-series** → mlx-lm
- **Linux server** → vLLM
- **Cross-platform CI** → llama.cpp

## 4. Key Findings

- **Finding 1:** vLLM is 30–50% faster than llama.cpp on the same NVIDIA GPU for batched inference. [2]
- **Finding 2:** For single-stream inference on a 16GB GPU, llama.cpp and vLLM are within 10–15% of each other — pick the simpler tool. [3]
- **Finding 3:** MLX on Apple M4 has 2–3x higher memory bandwidth utilization than llama.cpp Metal on the same hardware. [4]
- **Finding 4:** LM Studio (Bionic) is a wrapper, not an engine — its throughput equals llama.cpp server throughput. [1]

## 5. Open Questions

- vLLM ROCm support on RDNA 3 GPUs is still experimental — real numbers for RX 7900 XTX are sparse.
- Speculative decoding adds 1.5–3x throughput but requires a small draft model — production patterns are not standardized.
- Bionic's roadmap (closed-source) is unclear — whether it will diverge from llama.cpp.
